## 軸

原稿ファイルの書き方。「構造は HTML タグ、地の文は Markdown」という分担と、縦組みならではの下ごしらえ（ルビ・改行・縦中横）を渡す。

## 想定読者

一章を読み終えた人。Markdown は触ったことがあるかもしれないが、HTML を自分で書いた経験は少ない。

## 各節の担当

- VFM とは … Markdown の方言で、HTML を混ぜられる。
- なぜ HTML タグで区切るのか … 縦書きプレビューと、部品に名前を付けるため。
- 空行の作法 … タグの直後の空行で中身が段落になる。この章の山場。
- ルビ・縦中横・段落内の改行 … 縦組みの下ごしらえ。
- 部品の一覧 … 引用・注意・問いかけ・字下げ。見た目の数値は三章へ。

## 繰り延べ

- 版面の数値・書体 → 三章。前付けファイルの書き方 → 四章。規約ブロックの中身 → 六章（ここでは「見えない部品がある」とだけ言う）。

## 言い回しの注意

- 記法そのものを例示しない（コードを載せない方針）。記号の名前と働きを言葉で説明する。
- ルビの記法を本文に書くと、ビルドで本物のルビに変換されてしまう。説明するときは記号の名前で言う。

<h2>第二章　原稿の書き方</h2>

<h3>VFM という Markdown</h3>

vivliostyle の原稿は、VFM（Vivliostyle Flavored Markdown）という Markdown の方言で書きます。ふつうの Markdown と同じく、空行で段落を分け、記号で見出しや強調を表せます。そのうえで、本を作るための拡張がいくつか足されています。

VFM のもう一つの大事な性質は、HTML のタグをそのまま混ぜられることです。Markdown の記法で書きにくいところは、HTML で直接書いてしまえます。この本の原稿は、この性質を積極的に使います。

<h3>なぜ HTML タグで区切るのか</h3>

この本では、見出し・引用・囲み記事といった「構造」を、Markdown の記号ではなく HTML のタグで書いています。理由は二つあります。

一つ目は、縦書きのまま書きたいからです。VSCode の縦書きプレビュー拡張など、原稿を縦組みで表示しながら書ける道具があります。そうした道具では、Markdown の記号は行頭の飾りとしてそのまま縦に並んでしまうことが多く、どこが見出しなのかが一目でわかりません。HTML のタグにしておけば、記号と本文がはっきり分かれます。

二つ目は、部品に名前を付けたいからです。HTML のタグには「クラス」という名札を付けられます。「これは注意書きの枠」「これは読者への問いかけ」と名札を付けておけば、見た目は CSS の側で自由に決められます。原稿には「何であるか」だけを書き、「どう見えるか」は書かない。この分担が、あとで紙と電子の見た目を出し分けるときに効いてきます。

<blockquote>

<span class="small_heading">この章の要点</span>

原稿には部品の名前だけを書き、見た目はすべて CSS に任せる。
</blockquote>

<h3>空行の作法</h3>

HTML のタグを混ぜるときに、いちばんつまずきやすいのが空行です。

Markdown の決まりでは、HTML のタグで始まった部分は、次の空行が来るまで「生の HTML」として扱われます。その間に書いた文章は段落にならず、強調の記号も効きません。
逆に、開きタグのすぐ後に空行を一つ入れると、そこから先は再び Markdown として読まれ、ふつうの段落になります。

この本の原稿では、枠や囲みのタグを書いたら、開きタグの直後と閉じタグの直前に空行を入れる、と決めています。こうすると、枠の中にも外と同じように段落を書けます。

<div class="caution">
<span>ここに注意</span>

空行を忘れると、枠の中の文章が段落にならず、字下げや行送りが本文と揃わなくなります。見た目がおかしいときは、まずタグの前後の空行を確かめてください。
</div>

<h3>ルビ</h3>

縦書きの小説エディタの多くは、漢字の直後に二重山括弧で読みを書くと、それをルビとして表示します。縦書きで書くなら、この記法がいちばん手になじみます。

ところが VFM は、この二重山括弧の記法を知りません。VFM にも独自のルビ記法がありますが、縦書きエディタのプレビューとは互換がありません。

そこでこの本では、設定ファイルに置き換えの規則を一つ書き、ビルドのときに二重山括弧の記法を本物のルビに変換しています。親文字（ルビを振られる側）は、直前に続く漢字を自動で拾います。漢字以外に振りたいときや、拾う範囲を区切りたいときは、全角の縦棒で親文字の始まりを示します。
たとえば般若波羅蜜多《はんにゃはらみった》のように、原稿の側では読みを括弧で添えるだけです。

<h3>段落の中の改行</h3>

Markdown では、空行を挟まずに改行しても、同じ段落の続きとして扱われます。読みやすさのために、原稿では一文ごとに改行しておく書き手も多いでしょう。

ただし、この改行は消えるわけではありません。HTML になった段階では、段落の中に改行の文字が残っています。横書きの英文なら、これは単語の間の空白として自然に働きます。ところが縦組みの和文では、改行の隣がルビや約物（括弧や句読点）だと、改行がそのまま半角の空きとして残り、行の途中に妙な隙間ができてしまいます。

この本では、ビルドのときに段落の中の改行を詰める処理を入れています。漢字や仮名どうしの間は空白なしでつなぎ、英数字どうしの間だけは単語がくっつかないよう空白を一つ残します。引用やコードの中は、改行に意味があることが多いので触りません。

<h3>縦中横</h3>

縦組みの中に二桁の数字を書くと、そのままでは数字が横に寝てしまいます。これを一マスに正立させて収めるのが、縦中横（たてちゅうよこ）です。

この本では、縦中横にしたい文字を小さなタグで囲み、縦中横用の名札を付けています。たとえば第<span class="tcy">12</span>回のような書き方です。三桁以上になると一マスに収まりきらず潰れて見えるので、漢数字にするか、全角数字を縦に並べるほうが読みやすくなります。

<h3>部品の一覧</h3>

この本の原稿で使っている部品を挙げておきます。見た目はすべて CSS が決めているので、原稿の側では名札を付けて囲むだけです。

<div class="indent-1">

**引用・要点の枠** は、本文と書体を変え、背景に色を敷いた枠です。各章の「この章の要点」に使っています。

**注意の枠** は、見出しの小さなラベルを付けた囲みです。「ここに注意」のように、つまずきやすい点を本文から切り出すのに使います。

**問いかけの枠** は、章の終わりに読者への問いを置く枠です。大きな飾り文字が付きます。

**字下げの枠** は、この一覧のように、段落をまとめて一段下げる枠です。下げる深さを三段階で選べます。
</div>

これらのほかに、紙面には一切出てこない「見えない部品」も用意しています。著者自身のメモと、AI エージェントに向けた執筆の取り決めです。原稿のファイルを開くと書いてあるのに、PDF にも EPUB にも出てきません。後者の使い方は第六章で扱います。
