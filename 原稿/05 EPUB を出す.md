<h2>第五章　EPUB を出す</h2>

<h3>PDF との違いは三つだけ</h3>

EPUB を作るときも、原稿も設定ファイルも、PDF と同じものを使います。エントリの一覧も目次の仕組みもそのままです。違うのは、ビルドのときに渡す指定の三つだけです。

<div class="indent-1">

一つ目は、出力の形式を EPUB にすること。

二つ目は、ページ送りの方向を「右から左」と宣言すること。縦組みの和書は右綴じなので、リーダの画面でも左へ向かってページをめくる必要があります。この宣言が無いと、横書きの本と同じ向きにめくれてしまいます。

三つ目は、CSS を二枚重ねること。紙のための CSS の上に、電子書籍のための上書き用の CSS を重ねます。
</div>

この本では、それぞれ専用のコマンドを用意して、PDF と EPUB を別々に作れるようにしています。

<h3>ページはリーダが決める</h3>

紙の本では、どこでページが切り替わるかは作り手が決めます。三章で版面を細かく計算したのは、そのためでした。

ところが EPUB の多くは、リフロー型と呼ばれる形式です。リフローとは、文章を画面の大きさに合わせて流し直すことです。読者はリーダで文字の大きさを変えられ、画面の大きさもスマートフォンからタブレットまでさまざまです。ページの区切りは、読者が開いたその瞬間に、リーダが決めます。

このため、紙のために書いたページの決まりは、EPUB ではほとんどすべて効かなくなります。判型、版面の大きさ、天地やノドの余白、ノンブル、左右ページの振り分け。三章で積み上げたものの多くが、ここで消えます。

<blockquote>

<span class="small_heading">この章の要点</span>

紙の CSS は書き換えない。電子で効かないものだけを、上書き用の一枚で置き換える。
</blockquote>

<h3>上書き用の CSS の二つの仕事</h3>

紙の CSS を EPUB に合わせて直してしまうと、今度は PDF が崩れます。そこで紙の CSS には手を付けず、電子書籍のときだけ後ろに重ねる一枚を別に用意します。CSS は後から読んだ指定が勝つので、上書きしたいところだけを書けば済みます。
この一枚の仕事は、大きく二つです。

一つ目は、縦組みを確実に効かせることです。電子書籍リーダの多くは、少し古いブラウザの仕組みを中に持っています。そうしたリーダは、縦組みの指定を、昔の書き方（頭に特別な接頭辞を付けた書き方）でしか理解しないことがあります。そこで、新しい書き方と古い書き方を並べて書いておきます。

二つ目は、長さを相対的な値に置き換えることです。紙の CSS では、文字の大きさを級で、行の長さを「<span class="tcy">42</span> 字ぶん」で固定していました。これは紙では正しいのですが、画面ではあふれたり余ったりしますし、読者が文字の大きさを変えても反映されません。そこで、本文の文字の大きさを基準の一文字ぶんと読み替え、見出しや注記はその何倍、という比率で指定し直します。行の長さは指定を外して、画面の高さいっぱいに流します。

<div class="page-break"></div>

<div class="caution">
<span>ここに注意</span>

縦組みを指定するとき、文字の向きを「すべて正立」にする指定まで一緒に入れてしまうと、英単語まで一文字ずつ立って縦に積み上がってしまいます。和文の縦組みでは、文字の向きは既定のままにしておくのが無難です。
</div>

<h3>縦組みの割合指定の罠</h3>

画像を「ページいっぱいに」表示したいとき、横組みの感覚では「幅を <span class="tcy">100</span>%」と指定したくなります。ところが縦組みの EPUB では、これが効きません。

三章の方向の話を思い出してください。縦組みでは、ブロック方向、つまり行が並んでいく向きは左右です。リフローでは、この向きに文章がどこまでも続いていき、その長さはあらかじめ決まっていません。割合での指定は「何に対する割合か」が決まって初めて計算できるので、長さの決まっていない向きに対する割合は、計算できずに無視されてしまうのです。

一方、インライン方向、つまり行が伸びていく上下の向きは、画面の高さで決まっています。そこで縦組みでは、画像の大きさを「高さを <span class="tcy">100</span>%」と指定し、幅は画像の縦横比に任せます。原稿の画像に幅の指定が直接書いてあるなら、それも打ち消しておきます。

<h3>天地の余白</h3>

EPUB にはページの決まりが無いので、ページの余白も指定できないように思えます。ですが、縦組みの天地（上下）の余白は、本文全体を包む要素の上下の内側の余白で、ちゃんと制御できます。

縦組みでは、天地はインライン方向、つまり一行一行が伸びる向きにあたります。本文全体の上下に余白を取ると、それは「行の長さを少し縮める」ことになり、どのページのどの行にも同じように効きます。
反対に、左右の余白はブロック方向、つまりページ送りの向きにあたるので、流れの最初と最後に一度効くだけです。ページごとの余白には使えません。

ルビが密な段落は、ルビが行の外へはみ出すぶん、天地が詰まって見えがちです。この本では、引用の枠だけ天地の余白を少し広げています。リーダ自身にも余白の設定があることが多く、その値はこの上に足されます。

<h3>リーダの差</h3>

電子書籍リーダは、機種やアプリによって CSS への対応がかなり違います。
たとえば、要素を回転させたり、ずらしたりする指定に対応していないリーダがあります。この本の「問いかけの枠」には、紙では回転させて立てている飾り文字がありますが、あるリーダでは横倒しのまま表示されました。そこで EPUB では回転をやめ、文字の向きを正立させる指定で同じ見た目を作っています。回転と一緒に書いていた位置の調整も消えてしまうので、それは単純な余白の指定で置き換えています。

新しい指定を足すときは、まず古い書き方が用意されていないかを調べ、対応の厚いほうに寄せるのが安全です。

<h3>同梱するもの</h3>

EPUB は、本文と一緒に画像やフォントを一つのファイルに詰めて配ります。このとき vivliostyle は、作業用のフォルダにコピーした資産を、原稿から使っているかどうかにかかわらず同梱します。
画像のフォルダに、圧縮前の元画像や古い版の画像を置いたままにしていると、EPUB が何十メガバイトにも膨らむことがあります。設定ファイルで、原稿から使わない画像のフォルダをコピーの対象から外しておきましょう。PDF は使っている画像しか埋め込まないので、こちらには影響しません。

<h3>確かめ方</h3>

EPUB の中身は、実はただの ZIP 形式の圧縮ファイルです。展開すると、章ごとの HTML（正確には XHTML）が入っているので、それをブラウザで開けば、縦組みになっているか、行が画面の高さに収まっているかをざっと確かめられます。

ただし、最後は必ず実際のリーダで開いて確かめてください。ブラウザで正しく見えても、リーダで崩れることは珍しくありません。読者が使いそうなリーダを二つか三つ選び、そこで読めることを確かめるのが現実的です。
